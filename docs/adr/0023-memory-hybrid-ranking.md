# ADR 0023: Permission-filtered hybrid retrieval

Use PostgreSQL GIN full-text and pgvector HNSW cosine candidates, each restricted by the complete current authorization predicate before ordering/LIMIT. Combine candidate ranks with reciprocal rank fusion (k=60, equal lexical/vector weights); tie-break by record ID and deduplicate source references. Candidate sets are capped at 200; narrow filters when this bound is reached. These parameters were fixed before test-set evaluation; no test-set tuning is concealed. The initial synthetic benchmark contains 30 English and 15 Arabic/mixed paraphrase pairs and distractors. Record actual quality/latency in the report; an unavailable model is not a vector pass.

Normalize Arabic diacritics, tatweel, alef variants, final ya and Arabic digits identically in index/query SQL. Combine `simple` and English stemming. Natural-language queries use OR lexical candidates after a fixed small stopword list; ranking prefers stronger overlap instead of requiring every paraphrase token. Highlight codepoint offsets as React text/mark nodes; never interpret snippets as HTML.

Only the configured verified model/version participates in vector ranking. Missing/unusable local models fall back to full-text with a visible degraded status, including a requested vector search. A vector-only evaluation must reject degraded results rather than report fallback as vector quality. Query-bound, user/workspace-bound signed cursors expire after ten minutes; ranking is recomputed, so concurrent content changes can change order. No unauthorized total/skipped counts are returned. Evaluation uses a disposable database and synthetic data only.
