# ADR 0014: Closed read-only tool registry and shared-answer audiences

Accepted for Slice 4. The registry contains exactly nine read tools, each with a Pydantic schema forbidding extra properties, bounded strings/counts and capped JSON results. The workspace and requesting user come from the run, never from model arguments. Reuse channel_access/visible_channels and task access/get_project/get_task/serialization services used by REST. Task tools expose no private conversation links, link counts or linked activity. Search uses PostgreSQL full-text search across authorized message bodies and workspace-visible tasks; no embeddings.

A shared answer must be safe for its channel audience as well as the requester. Therefore private source channels are excluded except the destination itself, even if the requester belongs to another private channel. Public sources must be both requester-visible and enabled for the agent. The destination is checked for current requester membership/archive state and agent settings before provider IO, tools and publication. A changed source-channel permission fingerprint invalidates a result. No hidden names/counts/IDs are returned by context tools or error messages. The Agent panel states that unopened private channels are unavailable without enumerating them.

This is deliberately more conservative than requester-only access: copying private context into a public answer would leak it to other readers. Explicitly sharing text into a workspace-visible task remains the existing human action, not implicit link permission inheritance. Unknown or unauthorized calls are denied and audited; the whole run stops before a scripted provider can turn a denied request into a claimed answer.
